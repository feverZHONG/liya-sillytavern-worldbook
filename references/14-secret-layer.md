# 剧透层（私密层）· 第二本书怎么做

> 场景：一套卡里有一部分设定**不能随卡分发**（真相／剧透／黑历史），但自己玩的时候又缺不了。
> 判据：卡内书和公开书都装不下的「真相层」→ **另起一本独立书，卡不关联**。
> 机制依据：`12-worldbook-mechanics.md`（求值／预算）＋ `12b-mechanics-advanced.md` §2（角色过滤器）。

## 一、四个硬口径（机制决定的，不是偏好）

1. **卡不关联 = 不写任何卡的 `extensions.world`**（写卡字段＝接卡，见 SKILL §六）。
   **代价是「不自动生效」而不是「不生效」**：它不进 `characterLore`，必须由人手动加进 WI 面板 Global 列表（`selected_world_info`）或聊天绑定书。
   → 本层永远有一个**人工加载环节**，验收与台账里要写明，否则「我这边没反应」会被误当成 bug。
2. **知情分流用条目级 `characterFilter.names`**（值＝**卡文件名去扩展名**，改名即断链）。
   名单外角色发言时该条不注入；**群聊是按「当前发言成员」判**（逐成员轮转，见 `12b` §2）。
   ⚠️ **按主题分名单，不要全册一个名单**：一张卡可以同时出现在多个组里（组 A＝知道某真相的几个人，组 B＝某事件的受害链）——机制上每组各自生效，不需要合并成一个名单。
3. **order 段位**：独立书在预算处理顺序里**排最后**（默认 `character_first`，见主档 §0）；同组内按 order 降序保住。
   → 剧透层排在**关系层之上、卡内之下**。实例段位：卡内 300-390 ／ 关系 231-289 ／ **剧透 290-299** ／ 世界 110-178。**0 常驻**（常驻吃满每轮预算）。
4. **分发纪律**：不写卡、不随卡给、不进对外仓、不发群文件；台账里必须分开写「哪本给玩家、哪本只自己用」。

## 二、条目怎么写

- 照公开层五条规范（不写标题行／首句自报家门／只留事实／不复述关键词／**90-110 字**）。
  剧透条可以略长（承载「机构＋受害链」这类复合事实）——但把实测 token 记下来，别悄悄胖。
- **每条都要有出处**（文件名／行号／帖子编号）。剧透料最怕口口相传：宁愿标「待挖」，也不拿设想去填。
- 键照旧只收**专有名词**；已被误触发过的短键要收窄（实例：单字/两位编号会被日常句子蹭到 → 加限定词）。
- 与公开层**同键不算错**：跨书重叠＝互补（公开写机构级、剧透写内情），会同时注入但不打架。

## 三、验收口径（比公开层多两条）

| 测什么 | 期望 |
|:-------|:-----|
| 名单内角色 + 触发话术 | 命中，且**只命中该命中那条** |
| **名单外角色 + 同一句话** | **0**（`characterFilter 不符`）|
| 无关话术 | 0 |
| 体检 | `wb check <书> --card-dir <卡库>` 硬问题 0；`names` 断链校验全过 |
| 台账 | **卡文件 `git status` 为空**——一条都没被写 `extensions.world` |

判据：`wb sim <卡> "话术" --book <私密书>.json` **逐条**跑，别只看总量（总量看不出「谁被漏了」）。

## 四、落地顺序（可照抄）

1. **料源核对**：每条要点指得回出处；没料的那条挂「待定」，不硬写。
2. **知情矩阵**（哪条给谁）→ **先给人核**：这是唯一必须人类拍的部分（档案常常只点名了一部分知情人，其余是推定，要标出来）。
3. **小样 2 条** → 验写法。
4. **铺满** → `wb new <私密清单>.json --out <私密书>.json`。
5. **触发验收**（含名单外 0）＋ 台账登记（含分发纪律与「手动加载」这一句）。

## 五、踩坑

1. **别拿「群聊里过滤全灭」当结论**：只看进入群聊时 `setCharacterId(undefined)` 会判错——逐成员生成前会切成该成员，过滤照常生效（`12b` §2 有源码行号）。
2. **「单卡最大」必须按卡累加**：同一张卡可跨多个分流组，取组的最大值会**低估**（`wb check` 已修成 `per_card_totals`）。
3. **私密书不写卡 ≠ 不用管卡**：验证方式就是回头查一遍卡文件的 git 状态 + `tavern world --all` 体检，确认没有哪张卡被顺手挂上。
